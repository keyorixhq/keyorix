# Package invariants index

Every core package has an `INVARIANTS.md` next to its code: the rules a change there must
keep, each linked to the automated check that enforces it, or marked `UNGUARDED` with a
follow-up issue (label `unguarded-invariant`). **Read the relevant file(s) before changing
code in any of these packages.** See the root `CLAUDE.md`'s "Spec first, independent tests,
package invariants" convention for when this is required.

These are not invented — every entry traces to an ADR, an existing test/fuzzer/static guard,
`docs/security-closures.d/`, `docs/adr-conformance-enforced.tsv`, or a documented review
finding. If you discover or add an invariant while working in a package, add it to that
package's file in the same PR; if a change would have to break one, stop and ask rather than
silently removing it.

Separate module, not counted in the table below: the reusable differential-fuzzing kit
[`fuzzkit/diffkit/INVARIANTS.md`](../fuzzkit/diffkit/INVARIANTS.md) lives in the standalone `fuzzkit/`
module (built with `GOWORK=off`, like `cli/` and `operator/`). Its invariants
(`INV-FUZZDIFF-*`) are guarded by that module's own package tests and are deliberately
excluded from the counts table, which tracks production packages only.

## Maintaining this index

- **The package table is generated. Never edit the block between the `BEGIN GENERATED` and
  `END GENERATED` markers by hand.** Add or change an invariant only in its package
  (`<pkg>/INVARIANTS.md` or, for a new one, `<pkg>/INVARIANTS.d/`), then run
  `scripts/gen-invariants-index.sh` to refresh the index and commit the result. A package's
  first `INVARIANTS.md` gets its row by itself: do not add one. `--check` exits 1 when the
  block is stale (it is what `TestInvariantsIndexBlockIsGenerated` runs). If two PRs both
  regenerated the block and conflict, take main's `docs/INVARIANTS.md` and rerun the script;
  there is nothing to merge by hand.
- What the generator counts (the rules this section used to ask people to apply by hand): per
  package, the column-0 `- **INV-<PKG>-NN` bullets of its `INVARIANTS.md` (a bullet runs to the
  next column-0 line) plus one invariant per `INVARIANTS.d/INV-*.md` fragment; UNGUARDED is
  counted per bullet or fragment whose OWN text contains the word, never by a raw
  `grep -c UNGUARDED` of the file (every file's intro "Format: `INV-<PKG>-NN ... UNGUARDED
  (#issue)`" line contains the word and would inflate the count by one per file; the first
  draft of the hand-kept table was wrong this way). Guarded = Invariants − UNGUARDED. The
  standalone `fuzzkit/` module is excluded (see above). Rows are sorted by package directory
  in byte order (`LC_ALL=C`), so the output is identical on macOS and Linux. The label
  decorations `(+ `handlers`)`, `(+ `interceptors`)` and `(test-only)` live in the script.
  One consequence of "own text contains the word": a guarded invariant that mentions
  `UNGUARDED` for a sub-clause (for example `INV-KSYNC-fetcher-resource-bounded`'s
  `UNGUARDED-CORNER`) counts as UNGUARDED until that sub-clause is reworded.
- `internal/docsdrift` (`invariants_index_test.go`, `invariants_index_malformed_test.go`,
  `invariants_index_generator_test.go`) fails on a stale block, a package listed twice, a row
  whose Invariants is not Guarded + UNGUARDED, a Total row (there is none: two PRs editing the
  hand-kept one merged in the queue into two Total rows or a wrong sum, #4237; the test
  computes the column sums and logs them, run it with `-v` to read them), a row whose linked
  file does not exist or is not its own package's, a package or Total row outside the markers,
  a missing, duplicated or reversed marker pair, and any line of the table that matches no
  row pattern. The text outside the markers is hand-written and is never touched by the
  generator.

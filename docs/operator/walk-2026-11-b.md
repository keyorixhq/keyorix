# Operator runbook walk, 2026-11 (part b)

Second walk of the operator runbooks (PILOT-RUNBOOK-WALK-2), continuing
PILOT-RUNBOOK-WALK-1. The goal: an operator who follows a runbook word for word reaches its
stated end state. Every command below was run as written (real flags, real file modes) against
a server binary built from a fresh clone of `origin/main` (commit `d5370c92ce56`), natively,
on SQLite, on macOS. No Docker and no web browser were available: container variants and the
web UI are "pending e2e VM" and are marked as such.

Verdicts: **OK** (the runbook and the product agree), **DOC-WRONG** (the runbook was wrong or
silent; fixed in this change unless noted), **PRODUCT-DEFECT** (the product contradicts the
runbook; not fixed here, repro given).

Setup used by every walk: `keyorix-server admin init`, `admin encryption init`, `admin migrate`,
`admin recovery-key rotate`, a bootstrap token file (mode 0600), `keyorix system init`, a global
admin and a second user, both with TOTP enrolled (`security.require_mfa` is on by default), the
self-signed certificate `admin init` generates, trusted with `--ca-file`.

## 1. #4217: the flag named in a passphrase-file refusal

Not a runbook: the defect found while walking `admin encryption rotate-kek`. With
`--new-passphrase-file` pointing at a 0644 file the refusal said `--passphrase-file "..." is
group- or world-readable`. `crypto.PassphraseSource` now carries the flag prefix that
`RegisterPassphraseFlags` registered it under, and every refusal and `Describe` name the flag
the operator typed. The refusal and its exit code are unchanged. A table test covers the
arms missing, unreadable, mode 0644, wrong owner, empty and read error (over the size cap) for
`--passphrase-file` and `--new-passphrase-file`; red on `origin/main`, green on the branch.

## 5. `startup-refusals.md` and `startup-refusals-inventory.md`

Method. `internal/refusaldocs` already fails when a **Match** text of the operator page is no
longer in the Go sources (it passes on this tree). It does not look at the pasted output blocks,
the "from code" blocks or the inventory table. This walk checked those three:

1. Every backticked message in the inventory table (118 rows) was looked up in the non-test Go
   sources of `server/` and `internal/`, with adjacent string literals joined.
2. The first words of every line in every fenced block of the operator page (87 lines, known
   prefixes such as `Configuration is invalid:` removed) were looked up the same way.
3. Seven refusals were provoked with the native binary and compared by eye: unknown key,
   invalid `storage.type`, listener without a port, unsupported language, wildcard CORS origin,
   TLS enabled without certificate, weak cipher suite. All print the quoted text, and the
   process exits with status 1.

| Row | Observed | Verdict |
|---|---|---|
| inventory row `config.go:2931-2934` and operator page "gRPC listener problems" | the code says `server.grpc.tls.auto_cert: true is not supported: automatic (ACME) certificates are only available for the HTTP listener ...`; both documents quoted an older `gRPC TLS auto_cert is not supported; provide cert_file and key_file` that no build prints | DOC-WRONG, fixed in both (and the page now has the new text as a **Match**) |
| 17 other inventory rows | their backticked text contains `...`, `<table>` or a similar placeholder, so it is not a literal; the literal parts that were checked by hand (`must use https`, `is not a valid origin`, `must not be negative`, `require_existing_path`, `an admin operation is running against this database`, `re-wrap failed`, `permissions or ownership audit found unresolved issues`) are all in the sources | OK |
| operator page, 14 lines whose first words contain a formatted value | all 14 found by their literal parts (`HTTP server error`, `key file consistency`, `key file security`, `refusing to write a key set over another one`, `SCIM token is too weak`, `fips140 self-test failed on`, and so on) | OK |
| the other "Real output" blocks (47 in the page, 7 re-run above) | not re-run: most need a Postgres, a KMS, a FIPS build or a corrupted key set. The text check above holds for them. | not re-run |

Exit codes. The two documents have no per-row exit-code column. The operator page states the
exit status in three places: line 4 (the server "exits with status 1"), the "Port already in
use" output block (`exit=1`) and the sentence after it (`the process now exits with status 1`).
All three are true on `origin/main` today (the seven provoked refusals above exit 1).
[#4213](https://github.com/keyorixhq/keyorix/pull/4213) (EDGE-STARTUP-NOV-1, boot failures exit
78/75) is **not merged**, so those three places depend on it and were left as they are; whoever
merges #4213 must change them and say which refusals exit 78 and which exit 75.

## Product defects found (not fixed here)

1. **No self-service factor replacement with recovery codes only** (lost-totp section 2):
   `regenerate` and `disable` refuse a password and a recovery code for an account with TOTP
   (`internal/core/mfa.go` `requireReauth`); the OpenAPI text promises a recovery code.
2. **CLI prints no degraded note** (`cli/cmd/breakglass.go`; CLI-UX): `activate` and `list`
   ignore `degraded`.
3. **Posture counter ignores `degraded`** (`internal/core/compliance_posture.go:969`).
4. **Passphrase flag name** (#4217): fixed in this PR.

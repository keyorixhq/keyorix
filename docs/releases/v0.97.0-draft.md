## 1. Upgrade-impact summary

| Change | Who is affected | Action | Where |
|---|---|---|---|
| CLI refuses secrets given as flags (`--password`, `--value`, `--mfa-code`, notification `--url`, ... 15 in all) (#3325) | scripts and CI that call `keyorix` | move to `KEYORIX_*[_FILE]`, stdin, `--from-file`, `--url-file`; `KEYORIX_ALLOW_INSECURE_SECRET_FLAGS=1` is a temporary escape hatch | UPGRADING §6l, §6x |
| CLI exit codes 2–6 (#3316, merged) | scripts that test `$? -eq 1` | branch on 0/1/2/3/4/5/6 | UPGRADING §6m |
| `KEYORIX_BOOTSTRAP_TOKEN` must be ≥ 32 characters (#3341) | installs that pin a short token | `openssl rand -hex 32` | UPGRADING §6g |
| `server.grpc.tls.auto_cert: true` refused (#3365, AUTH-2) | configs with that line | remove it; give gRPC a cert | UPGRADING §6t |
| `mfa.failed` and the other `*_failed` audit events now `success=false` (#3365, AUTH-2) | SIEM rules, exports, reports | match on `event_type` for history | UPGRADING §6u |
| PostgreSQL `session_replication_role` must be `origin` (#3366) | databases/roles with a non-origin default, Helm `postgresql.settings` | remove the setting before the new server starts | UPGRADING §6n |
| Grants fail closed when the audit row cannot be written (#3367); break-glass commits degraded instead | automation that creates users/roles/shares/tokens | retry a **500** on those calls only after checking the object or grant does not already exist (the REST answer is a generic 500, the reason is in the server log; another 500 on a create may have committed) | UPGRADING §6o, §6o.1 |
| Schema compatibility floor 3 (epoch 8): a v0.96.x binary refuses to start on an upgraded database (#3364) | everyone who may roll back; multi-replica rollouts | rollback is a restore | UPGRADING §6q, §7, upgrade checklist |
| PostgreSQL: the server checks it holds the database's DEK (#3344) | multi-replica installs and anyone rotating the DEK | upgrade every replica before the next DEK rotation | UPGRADING §6s |
| SCIM no longer creates or manages `sso:` accounts (#3493) | installs with SCIM next to SSO | run the check query in §6v | UPGRADING §6v |
| "Last used" in access recertification means "within the review period" | recertification reviewers | raise `recertification.cadence_days` for a longer look-back | UPGRADING §6w |
| SECURITY: Vault access migrated with `keyorix-migrate` v0.96.0 to v0.96.3 may hold grants wider than the Vault policy | installs that ran `keyorix-migrate vault apply-access` | run `keyorix-migrate vault audit-access` and revoke what it lists | UPGRADING §6y |
| Roles carry an assignable scope (schema epoch 7, #3546) | API clients that create roles and grant them without `project_id`; `system_*` roles granted on a project | send `assignable_scope` on role create, or grant without a project; read the start-up `WARNING` | UPGRADING §6z |
| `audit_durability` defaults to `standard` on PostgreSQL (#3268) | PostgreSQL installs | add `audit_durability: strict` to keep the old behaviour | UPGRADING §6c |
| PostgreSQL `verify-full`/`verify-ca` needs `ssl_root_cert`; `ssl_mode` allowlist; Compose Postgres over TLS (#3162, #3189, #3203) | external PostgreSQL, Compose | see UPGRADING §2 | UPGRADING §2 |
| Listener limits: REST headers 64 KiB (431), gRPC idle/handshake/stream/metadata caps (#3312) | clients with very large headers/metadata | none normally | UPGRADING §6p |
| Audit list: `offset` past the newest 10,000 events answers 400, bounded `total` (#3260) | API clients that page by `offset` | use `cursor` | UPGRADING §6p |
| `admin init` writes `environment: production`; the value `development` replaces `allowed_origins` (#3217) | configs written by hand with `environment: development` | change it to `production`/`staging`/`local` | UPGRADING §6b |
| Server binds 127.0.0.1 by default (#2946) | already in v0.96.0 | — | UPGRADING §6a |

Helm: **no value was renamed or removed on main.** New values since v0.96.1 are additive (`server.trustedProxies`, `server.accessLog.onSinkStall`, `server.goMemLimit[Percent]`, `server.probes.*`, `postgresql.settings`, `auditDurability`, `externalDatabase.{sslRootCert,caSecret,pooler}`, `networkPolicy.egress.{databaseTo,kmsTo,kmsPorts}`, `networkPolicy.ingress.*`, `monitoring.serviceMonitor.*`) plus, from the Helm PRs that have merged since (#3305, #3308, #3366), `server.singleWriter`, `server.podDisruptionBudget.*`, `server.topologySpreadConstraints`, `web.topologySpreadConstraints` (diff of `values.yaml` against v0.96.1 on 2026-10-23: 175 lines added, no key removed or renamed). `postgresql.auth.password` lost its empty placeholder (the render already failed when it was unset). `server.replicas` above 1 is now allowed, and the render fails unless the keys volume is `ReadWriteMany` and `singleWriter` is false; `postgresql.settings.session_replication_role` is refused.

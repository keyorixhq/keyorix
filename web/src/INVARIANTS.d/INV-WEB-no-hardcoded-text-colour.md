- **INV-WEB-no-hardcoded-text-colour** A text colour in `web/src` comes from a theme token in `index.css` (`var(--success)`, `var(--warning)`, `var(--danger)`, ...), not from a hex literal, and the status hexes `#16a34a`, `#d97706`, `#dc2626` appear in no string literal at all. Why: a hex bypasses `INV-WEB-theme-token-contrast` and does not follow the theme, so the green `#16a34a` badge text read 3.3:1 on white and `var(--text-danger, #dc2626)` hid a token that was never defined. Guard: `__tests__/structure/hardcodedTextColours.test.ts` (TypeScript AST scan of every non-test `.ts/.tsx`; the status hexes are a hard ban, every other `color:` / `text-[#hex]` hex is a ratchet in `KNOWN_HARDCODED` that may only shrink; calibration cases included). **Not covered**: background, border, fill and stroke colours, colours built at run time (`rgb(...)`, named colours), `element.style.color = ...`, and the existing legacy hexes listed in `KNOWN_HARDCODED`, which are still unchecked for contrast.

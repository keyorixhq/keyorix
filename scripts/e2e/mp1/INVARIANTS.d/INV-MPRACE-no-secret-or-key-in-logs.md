- **INV-MPRACE-no-secret-or-key-in-logs** No secret value the harness ever writes, and no raw DEK/salt key byte, appears verbatim in any replica's log file. Why: a confidentiality leak into logs is a serious defect and multi-process load exercises more log paths (per-process loggers, concurrent request logging) than a single process does; every value written anywhere in the package is registered as a canary and scanned (backlog I1, oracle: canary). Guard: the post-run scan in `TestMain` (`postRunCanaryScan`, `scripts/e2e/mp1/cluster_fuzz_test.go` + `oracles_test.go`), which runs after `m.Run()` in every test process, including each `-fuzz` worker, and fails the run on any hit or unreadable log; it reads every replica log of every cluster the process started, including the SIGKILLed replica's preserved pre-restart log. `TestZZCanaryNoSecretInLogs` is only an early in-run signal: Go runs Tests in source order and Fuzz targets after them, so it never sees the fuzz targets' values. Red/green on `scanLogForSecrets` in `TestRedProof_Canary` and on `postRunCanaryScan` in `TestRedProof_PostRunScan`. Not run in CI: no workflow runs `-tags e2e ./scripts/e2e/mp1` against Postgres, so this guard holds only for manual runs.

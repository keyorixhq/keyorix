- **INV-MPRACE-no-secret-or-key-in-logs** No secret value the harness ever writes, and no raw DEK/salt key byte, appears verbatim in any replica's log file. Why: a confidentiality leak into logs is a serious defect and multi-process load exercises more log paths (per-process loggers, concurrent request logging) than a single process does; every value written anywhere in the package is registered as a canary and scanned (backlog I1, oracle: canary). Guard: the incremental log scan `scanNewLogOutput` (`scripts/e2e/mp1/oracles_test.go`), run at the end of every `FuzzMP1MultiProc` and `FuzzMP1UniqueCreate` iteration (a hit fails the iteration, so under `-fuzz` the engine reports it and keeps the input), in `TestZZCanaryNoSecretInLogs`, and in `TestMain` after `m.Run()` for the output written after the last of those (a hit sets exit 1). It reads every replica log of every cluster the process started, including the SIGKILLed replica's preserved pre-restart log, and treats an unreadable log as a failure. It is complete because every value is recorded before it is sent. `TestZZCanaryNoSecretInLogs` alone would not be: Go runs Tests in source order and Fuzz targets after them, and under `-run '^$' -fuzz` no Test runs. Red/green on the matcher in `TestRedProof_Canary`, on the incremental scan in `TestRedProof_IncrementalScan`, and live with `KEYORIX_MP1_CANARY_PLANT=1` (plants a recorded value in an extra cluster log; the run must fail). Not run in CI: no workflow runs `-tags e2e ./scripts/e2e/mp1` against Postgres, so this guard holds only for manual runs.

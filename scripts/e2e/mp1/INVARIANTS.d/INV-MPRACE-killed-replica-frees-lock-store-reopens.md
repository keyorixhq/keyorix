- **INV-MPRACE-killed-replica-frees-lock-store-reopens** After `SIGKILL` of one replica mid-write-load, the surviving replicas keep committing writes (each an audit append under the advisory lock) within a bounded time — the dead backend's torn-down Postgres connections released any session-scoped advisory lock it held — and the killed replica, restarted against the same config/keys/port, becomes healthy and serves a fresh authenticated write, i.e. the shared store reopens (KEK re-derive, DEK unseal, schema re-attach, pool rebuild) with no hand repair. Why: HA means a crashed replica neither wedges the cluster (a session advisory lock survives the holder is the specific hazard) nor requires operator intervention to rejoin (backlog I1, oracles #4/#6). Guard: `TestKilledReplicaNoStuckLock` (`scripts/e2e/mp1/oracles_test.go`) — uses its own cluster; re-verifies the audit chain after the kill+restart. The restart half is a liveness check with no separate red proof: a failed boot or write fails the test directly. Not run in CI: no workflow runs `-tags e2e ./scripts/e2e/mp1` against Postgres, so this guard holds only for manual runs.

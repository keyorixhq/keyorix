PART A — fuzz-corpus #153 (FuzzDSNHostsCoverDriverHosts), variant sweep
====================================================================

Context already established (do not re-derive, just verify):

- internal/core/dsn/dsn.go's SplitDSNHostList (around line 79) strips bracket
  wraps around a host= field ONCE:
    if strings.HasPrefix(part, "[") && strings.HasSuffix(part, "]") && len(part) > 2 {
        part = part[1 : len(part)-1]
    }
  For the already-triaged crasher `host=[[]]`, part="[[]]" strips once to
  "[]" — a bracket pair with nothing inside, which nothing downstream can
  dial or resolve, so it's benign (that's why #153 was filed as CANDIDATE
  rather than closed: the *mechanism* is real, but that exact input is a
  dead end).

- The UNEXAMINED case is a double-bracket wrap of a VALID IPv6 literal, e.g.
  host=[[::1]] (or [[fe80::1]], [[2001:db8::1]], etc). Trace it by hand first
  to know what to test for: part="[[::1]]" (7 chars) strips ONCE to "[::1]"
  — still bracket-wrapped, because the strip only runs once, not in a loop.
  That stripped-once value is what SplitDSNHostList returns as the "host".

- Then validateAdminDSNSingleHost (internal/core/dynamic_secrets.go, near
  line 170) is given that string:
    - net.ParseIP("[::1]") returns nil (ParseIP does not accept bracket
      syntax), so it does NOT take the literal-IP branch.
    - No "%" present, so the zone-ID branch is skipped.
    - Falls to net.LookupHost("[::1]") — confirm experimentally what this
      actually returns on this system/Go version. If it errors (which the
      zone-ID comment two lines above implies is the expected shape for a
      non-parseable-as-IP, non-resolvable string), validateAdminDSNSingleHost
      returns nil — "unresolvable at register time, skip validation" — i.e.
      this host is NOT checked against the private/link-local blocklist at
      all.

The open question: does the ACTUAL DRIVER (pgx/pgconn for Postgres,
go-sql-driver/mysql for MySQL — this is key-value host= syntax, so Postgres
and MySQL both apply; mongo uses URI syntax, out of scope for this exact
variant) end up dialing that same "[::1]"-shaped string as the literal
address ::1 (or whatever address was double-bracketed), i.e. does validation
get SKIPPED on a host the driver WILL successfully resolve/dial? That's the
bypass. Or does the driver also choke on the double-bracket residue and
simply fail to connect (benign, same shape as the already-triaged `[[]]`
case)?

Do this, mirroring what internal/dynamic's FuzzDSNHostsCoverDriverHosts
already does (read that fuzzer first — it directly drives pgx's own
config-parsing / mysql driver's own DSN parsing and compares against
dsn.ParseDSNHosts's output; reuse its harness functions rather than
hand-rolling new driver calls):
  1. Write a focused unit test (not a fuzz corpus addition yet) that feeds
     `host=[[::1]]`, `host=[[fe80::1]]`, `host=[[::1]],otherhost` (multi-host
     list, since SplitDSNHostList is comma-split per entry) through
     dsn.ParseDSNHosts and asserts what comes out.
  2. Feed the SAME dsn string to pgconn.ParseConfig (postgres) and to
     go-sql-driver/mysql's own DSN parser, and compare: does the driver's own
     notion of "host to dial" match, or diverge from, what ParseDSNHosts
     returned? Specifically: does the driver successfully extract a dialable
     address from the double-bracket form (meaning it WILL try to connect to
     it, defeating the purpose of validateAdminDSNHost skipping it), or does
     it also fail/reject (benign)?
  3. If step 2 shows the driver treats it as dialable while validation skips
     it: confirm end-to-end by actually registering a dynamic-secrets config
     with that admin_dsn against validateAdminDSNHost directly (call it, not
     just the pieces) and confirm no error is returned, THEN confirm (via a
     short net.Dial-level check, not a real backend — e.g. that
     net.ResolveTCPAddr or an equivalent on "[::1]:5432"-shaped input
     succeeds) that this host is in fact reachable/dialable. That combination
     (validator says OK, network layer says reachable) is the actual bypass;
     either alone is not.
  4. If the bypass is confirmed live: the fix is almost certainly making the
     bracket-strip in SplitDSNHostList a loop (`for strings.HasPrefix(...) &&
     strings.HasSuffix(...) { part = part[1:len(part)-1] }`) instead of a
     single `if`, so "[[::1]]" fully unwraps to "::1" and is then correctly
     recognized by net.ParseIP as a checkable literal. Before writing it,
     confirm this loop form doesn't change behavior for any EXISTING passing
     test or seed corpus entry (run the existing dsn package tests and the
     FuzzDSNHostsCoverDriverHosts seed corpus first to get a baseline). Red
     proof: a test with the double-bracket valid-literal input fails pre-fix
     (validator wrongly skips a private/link-local address) and passes
     post-fix. This is a one-function, mechanical fix (loop instead of if) —
     write it and the red/green test if and only if step 3 actually confirms
     a live bypass. If step 2 or 3 shows it's benign (driver also can't dial
     it), do NOT write a fix — write up why it's benign and add one pinned
     regression seed (same treatment as the `[[]]` case) so the behavior is
     locked in either way.
  5. Either way, add whatever input(s) you tested as seeds under
     testdata/fuzz/FuzzDSNHostsCoverDriverHosts/ (or wherever the existing
     seeds for that fuzzer live — check first) so this exact variant space
     doesn't go unwatched again.

Do NOT touch validateAdminDSNHost itself unless step 3 proves it's wrong —
the likely fix, if any is needed, is in SplitDSNHostList's bracket-stripping,
not in the validator.

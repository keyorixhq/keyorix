### Changed
- **The Kubernetes operator and the k8s sync agent no longer wipe synced Secrets on a 401.** A 401 from Keyorix means the operator's / agent's own credential is invalid, expired or rotated, not that a workload's grant was cut. Every synced Secret is now kept untouched, whatever `prunePolicy` / `pruneOnRevoke` say, and the failure is reported and retried with backoff: operator `Ready=False` reason `KeyorixAuthFailed` (replaces `UpstreamAccessRevoked`), one Warning Event on entry, counter `keyorix_operator_auth_failures_total`; k8s-sync counts the target `failed` and `auth_failed` (`keyorix_k8s_sync_secrets_total{outcome="auth_failed"}`, `/status` `auth_failed`, a `KeyorixAuthFailed` log line). Once the credential is fixed the next reconcile syncs normally. The classification comes from the HTTP status alone. A 403 / 404 for a specific secret (grant revoked / secret deleted) is unchanged: it still wipes per `prunePolicy` / `pruneOnRevoke`, behind the mass-revocation circuit breaker. Decision: Andrei, 2026-10-13. The operator and k8s-sync docs now carry a per-cause table (unreachable/5xx/401: keep; 403/404: prune per policy; suspended: `onSuspend`; expired: keep and warn).

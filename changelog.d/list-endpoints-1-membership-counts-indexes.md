### Changed
- **More list endpoints no longer query per row, and the audit views sort by an index.** The users list (project counts), the project access review, the secrets inventory CSV and the machine audit report now use one batched lookup per kind instead of per user, secret, owner or identity: a 100-user page went from 305 statements to about 15, a 1000-secret access review from 1690 to a few dozen, the machine audit report from 204 to 5. `audit_events` gains indexes on `event_time`, `(secret_node_id, event_time)` and `(project_id, event_time)`, so `GET /audit/logs`, the per-secret trail and per-project views read an index range instead of sorting the whole table (about 22 ms to 0.3 ms at 200k rows on SQLite, 10 ms to 1-2 ms on PostgreSQL). Responses and pagination are unchanged. The indexes are created by the schema migration on startup; on a very large audit table that one-time build holds the table briefly.

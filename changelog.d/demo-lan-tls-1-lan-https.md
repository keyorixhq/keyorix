### Added
- **One-command HTTPS demo box for a LAN or an air-gapped network.** `deploy/demo-lan/install.sh --bin-dir <linux binaries>` creates a local CA once (ECDSA P-256, 10 years, key readable by root only, `extendedKeyUsage serverAuth` and X.509 nameConstraints limited to the box's own address and names, no e-mail or URI), signs the server certificate with it (825 days or less, never past the CA's end, re-issued automatically when fewer than 30 days are left; a WARNING from 90 days before the CA ends), starts a fresh server on `0.0.0.0` with TLS as the unprivileged system user `keyorix-lan` (hardened unit: no capabilities, `ProtectSystem=strict`, only its state directory writable, the CA key hidden), seeds the demo org through https and ends with `scripts/demo/check.sh --used`. It prints the CA file, its SHA-256 fingerprint and the trust commands for macOS, Windows and Linux; trusting the CA once in each browser is the only manual step. No ACME, no public DNS, no manual openssl. Refuses to run over an existing `keyorix.db` unless `--reuse`, refuses an existing `--dir` that is not root's, is writable by others or is populated by something else, and deletes nothing. See `docs/demo/LAN-TLS.md`.

### Testing
- **Tests for the LAN demo installer.** `deploy/demo-lan/demo_lan_test.go` checks the generated CA and certificate with Go's verifier and openssl (name constraints, EKU, SAN, key modes and groups, validity capped to the CA, the 30-day renewal threshold without a re-issue loop near the CA's end; certificates the CA key signs for another name, a neighbouring address, an e-mail address, a URI, code signing or a TLS client are rejected), the systemd units as `install.sh` renders them (non-root user, root-only renewal, hardening), the installer's refusals (including an existing shared or foreign `--dir`, whose mode it leaves alone), run-time address detection, that no lab address is committed, and that the files `install.sh` copies cover what `check.sh` calls.

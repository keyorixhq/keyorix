### Changed
- **Upgrade note: the first audit scans after an upgrade walk the history once.** Two background jobs do a one-off catch-up over the existing audit table, then read only new rows. Neither blocks startup and neither needs any action. (1) The `recover_admin_alert` job (every 10 minutes) stores the highest audit id it has examined. An install that has never used recover-admin has no stored mark, so its first run reads ids from 0 up to the current highest id, in windows of 100,000 ids, saving the mark after each window. A restart or lease handover resumes at the last saved window, and each recover-admin use is still alerted exactly once. An install that has used recover-admin resumes from its last alerted id. (2) With audit checkpoints enabled, the audit-checkpoint scheduler re-walks the whole chain in 7 segments, one per tick (the default tick is 24 hours, so about a week; each segment is at least 100,000 ids). Until that first cycle completes, `keyorix audit verify` reports `NOT PROVEN` rather than `VALID`; run `keyorix audit verify --full` to get a definite answer immediately.

### Testing
- **resguard no longer bills the first input of a fuzz worker for the harness's own setup.** Since 2026-11-21 the first `fuzzutil.Guard` call in a process made the stall monitor's first `runtime/metrics` read (~10 KiB) inside the measured window, so under `go test -fuzz -parallel=6` a tiny seed that landed first in a worker failed its calibrated alloc budget (`FuzzDigitorusTimestamp` on its own seed corpus). fuzzutil now does that read at package load and `resguard.New` primes Guard's monitor, runner and timer before any input is measured (INV-FUZZUTIL-first-guard-call-allocates-nothing-extra). No budget was widened.

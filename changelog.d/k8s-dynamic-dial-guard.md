### Security
- **Kubernetes dynamic secrets now refuse private `api_server` destinations at dial time.** The engine ignored `allow_private_network_targets`, and the host check core runs before each issue resolves the name separately from the HTTP transport's own lookup, so a hostname rebound between the two could still reach a private address. An explicit `api_server` now goes through the same dial-time guard as the postgres, mysql, mongodb and redis engines; setting `allow_private_network_targets` keeps the old behaviour. The in-cluster API address is unaffected. Guarded by `TestKubernetesEngine_DialGuard`.

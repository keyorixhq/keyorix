### Fixed
- **The evidence-pack and audit-checkpoint signing keys are called KEK-derived everywhere users read about them.** The OpenAPI and gRPC text, `keyorix compliance verify --help`, `docs/cli-reference.md`, the man page, the generated web API types and the code comments said DEK-derived. The OpenAPI text for evidence verify also promised that a signature made under a superseded DEK version (after a key rotation) is unverifiable. That is not what happens: a DEK rotation does not change the key. A pack signed before a KEK change (`rotate-kek` or a KEK-provider migration) is reported as `valid: false` with a "superseded key version" reason, `key_version` and `current_version`, not as tampered. The checkpoint endpoint text no longer tells operators to re-baseline after a DEK rotation; it is a KEK change that makes the next checkpoint a re-baseline. `TestEvidenceVerify_PackSignedBeforeKEKChangeIsUnverifiable` derives the keys from two real KEKs and asserts the described behaviour.

### Changed
- **SQLite accepts `storage.database.audit_durability: standard`, for read audits only (ADR-112 Amendment 7).** It used to refuse to start. At `standard` a SQLite server opens one extra connection to the same database file with `synchronous=NORMAL`, and the audit flusher commits a batch on it only when every row is a successful secret-value read audit. Secret mutations, their audit rows, denied reads and mixed batches stay on the `synchronous=FULL` pool. A process crash loses nothing; an OS crash or power loss can lose a tail of read-audit rows written since the last disk sync, with no time bound on SQLite, never a gap in the audit chain or a committed mutation. The SQLite default stays `strict` and opens nothing new. Guarded by `INV-STORAGE-sqlite-normal-conn-read-audit-only`; upgrade note in `docs/upgrading.d/sqlite-audit-durability-standard.md`.

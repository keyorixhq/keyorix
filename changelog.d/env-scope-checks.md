### Security
- **`keyorix run` and `keyorix rbac` no longer pick the wrong environment when two names differ only in case.** Environment names are unique per project case-sensitively, so `prod` and `Prod` can coexist; the CLI matched them case-insensitively and took the first listed, so `keyorix run --env Prod` could inject the secrets of `prod`, and an `rbac` command could grant a role on the wrong environment. An exact name now wins; a name that matches only case-insensitively is accepted only if exactly one environment matches, otherwise the command refuses and names the candidates.
- **The Kubernetes sync agent now checks the scope of what the server returns.** The matching entry of the secret list must name the agent's project and the resolved environment, and the value response must carry the requested secret id, project and environment. A mismatch fails closed without removing the synced copy (it is not treated as "secret gone"). Previously the agent relied on the server having filtered the list correctly.

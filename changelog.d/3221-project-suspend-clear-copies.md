### Added
- **Freeze a whole project and also clear its synced Kubernetes copies.** `POST /api/v1/projects/{id}/secrets/suspend-all` takes the same optional `clear_synced_copies: true` as the single-secret suspend (web: a checkbox in the project's *Freeze all secrets* dialog, with the rotation note; CLI: the new `keyorix project suspend-secrets --id N [--reason ...] [--clear-synced-copies]` and `keyorix project resume-secrets --id N`). It needs the same permission as the project freeze, and each secret it suspends gets the per-suspension marker exactly as a single-secret suspend does (an already-suspended secret without it is upgraded, one with it is left alone); `resume-all` clears it. One `secret.bulk_suspend_attempted` audit event records the choice (`clear_synced_copies=true`) and the number of secrets targeted before any secret is touched; if that event cannot be recorded the request fails and nothing is suspended. A plain freeze is unchanged, apart from that event now being written before the freeze (its count is the secrets targeted, not the ones that succeeded). The project suspend/resume routes are now in the OpenAPI document.

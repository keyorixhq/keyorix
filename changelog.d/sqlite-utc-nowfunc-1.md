### Fixed
- **A server on a host with a non-UTC time zone no longer stores zoned timestamps on SQLite that it cannot read back.** GORM's `created_at` / `updated_at` stamp now uses UTC (`NowFunc` in the storage factory), and a machine identity's `updated_at` (assigned from the host-zone clock in core) is converted to UTC on save. Before, such a host stored `machine_identities.updated_at` as `2026-10-31 12:44:58.849121 +1400 OT m=+0.45…`, `GetMachineIdentity` failed to scan it, and `POST …/machine-identities/{id}/tokens` answered 404. `last_used_at` written when a personal access token or machine credential is used is now stored in UTC too (a used credential could not be read back on such a host), as are the session `absolute_expires_at` copied on refresh, the SSO/SAML login-state expiry and a new user's one-time-password expiry. Existing rows already stored with a zone suffix are not rewritten.

### Documentation

- `docs/CONFIGURATION.md` documents 56 more config keys, each read against the code for default, unit and effect: `storage.database.host/port/name/user`, the `server.grpc` keys that only the HTTP listener reads, SAML provider keys, `oidc.issuers[].max_token_age_seconds`, `membership.domain_allowlist`, `secret_value_policy`, `secret_name_policy`, the three `classification` gates, `audit.siem.token/spool_dir`, `notifications.email.broadcast_to`, `notifications.webhook.signing_secret`, `expiry_reminders`, `license_expiry`, `read_quota_alerts`, `anomaly_alerts.business_hours/baseline_quarantine`, `license.*`, `minimum_cli_version` and `kms_encryption_context`. Security-relevant defaults (off, unsigned, no restriction) are stated plainly.
- `docs/CONFIGURATION.md` no longer says `server.grpc.tls.allowed_ciphers` applies to HTTP only (gRPC reads it too), and the notifications intro now says that webhook, Slack and Teams receive only the deployment-wide broadcasts (compliance digest, auto-rotation failure); per-user notifications go to the email channel only.
- `docs/CONFIGURATION.md` no longer calls the audit checkpoint scheduler opt-in: it is on by default whenever encryption is configured, and `insecure_disable_audit_checkpoints: true` is the only way to turn it off.

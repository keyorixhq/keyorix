### Security
- **A MongoDB dynamic-secret `admin_dsn` can no longer turn certificate verification off past the operator's transport policy (#4374).** `tls=true&tlsInsecure=true` (or `sslInsecure=true`) passed the TLS requirement while accepting any server certificate. It is now refused with a clear message unless `dynamic_secrets.insecure_allow_plaintext_dynamic_secret_transport` is set, in which case it is allowed and logged as a warning. Revoking a lease that was issued with the option drops it and verifies the certificate, so against a target whose certificate the server does not trust the revoke fails and the lease stays `revoke_failed` with its MongoDB user still live: see `docs/upgrading.d/mongodb-admin-dsn-tls-insecure-refused.md` for what to do before and after upgrading. The same change closes a downgrade: a `mongodb+srv://` admin_dsn that wrote `TLS=false` or `SSL=false` (any option-name case) connected without TLS because the requirement was read case-sensitively while the driver is not.
- PostgreSQL and MySQL admin_dsn transport options (`sslmode`, `tls`) are unchanged: those two backends are not covered by the transport flag today, which is documented here and pinned by tests until the question of extending it is decided.

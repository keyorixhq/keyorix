### Security
- **PostgreSQL and MySQL dynamic-secret targets now follow the transport policy (#4374).** Without `dynamic_secrets.insecure_allow_plaintext_dynamic_secret_transport`, an `admin_dsn` must verify the server certificate: `sslmode=verify-full` for PostgreSQL (`verify-ca` only with a root certificate installed on the Keyorix server), `tls=true` for MySQL. `sslmode=disable`, `allow`, `prefer` (also the default when `sslmode` is not set), `require`, MySQL `tls=false` (also the default), `skip-verify`, `preferred` and `allowFallbackToPlaintext=true` are refused when a config is created or its `admin_dsn` replaced, decided from the parsed driver settings (so a `PGSSLMODE` environment value counts too). **Who is affected:** project admins whose PostgreSQL or MySQL configs use one of these settings. **Soft period:** a config stored before the upgrade keeps issuing for this release, with a WARNING and a `dynamic_lease.insecure_transport` audit event on every issue; the next release refuses it. **How to fix:** give the database a certificate the Keyorix server trusts and set `sslmode=verify-full` / `tls=true` with `keyorix dynamic-secret set-admin-dsn <config-id>`, or have the operator set the insecure-transport flag. Upgrade note: `docs/upgrading.d/sql-admin-dsn-transport-policy.md`.

### Testing
- **Cross-layer authz operation matrix.** `devtools/authzmatrix` derives every mutating and secret-value-reading operation from type-checked SSA. For each one it records the core entry point, REST route and gRPC method, and whether core itself refuses or leaves authorization to the transport. It is calibrated against the FIX-1 grant guards, with a red self-test. Output: `server/authzdiff/MATRIX.md` and `matrix.json`.
- **Cross-layer authz differential harness.** `server/authzdiff` runs each operation for the same principal and inputs on three layers: core called directly, the real REST router and the real gRPC server, each leg on its own copy of a seeded SQLite template (synthetic fixtures only). Two oracles: the layers agree, and each layer matches a reference model over the role's actual permissions. Principals are fixed named ones plus permission sets generated per operation, held directly, through a group or by a machine. Coverage over every in-scope operation is derived from `matrix.json` (`COVERAGE.md`, `COVERAGE-ALL.md`). The default `go test` run takes about 3 s; the exhaustive sweep (`AUTHZDIFF_SWEEP=1`) and the planted-defect self-test (`AUTHZDIFF_PLANTS=1`, CI job `authzdiff-plants`: nightly, manual dispatch and `ci:full` PRs) are opt-in.

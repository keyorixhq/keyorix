### Testing
- **Cross-layer authz operation matrix.** `devtools/authzmatrix` derives every mutating and secret-value-reading operation from type-checked SSA (not from file or symbol names). For each one it records the core entry point, REST route and gRPC method, and whether core itself refuses or leaves authorization to the transport. It is calibrated against the FIX-1 grant guards, with a red self-test. Output: `server/authzdiff/MATRIX.md`; outcome semantics in `server/authzdiff/OUTCOMES.md`.
- **Cross-layer authz differential harness.** `server/authzdiff` runs each operation as a fixed principal set (no role, viewer, project admin, global admin, a custom role with a fuzzed permission subset, a machine token, actor 0, an expired grant) on three layers: core called directly, the real REST router and the real gRPC server. Every leg runs on its own fresh copy of a seeded SQLite template. Oracle 1 asserts the layers agree. Oracle 2 compares each layer against a reference model over the role's actual permissions. `TestAuthzDiffSmoke` runs by default; the exhaustive sweep (`AUTHZDIFF_SWEEP=1`) and `FuzzAuthzDiff` record findings without failing unless `AUTHZDIFF_STRICT=1`. Findings: `server/authzdiff/REPORT.md`.

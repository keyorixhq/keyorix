### Testing
- **Cross-layer authz operation matrix.** `devtools/authzmatrix` derives every mutating and secret-value-reading operation from type-checked SSA (not from file or symbol names). For each one it records the core entry point, REST route and gRPC method, and whether core itself refuses or leaves authorization to the transport. It is calibrated against the FIX-1 grant guards, with a red self-test. Output: `server/authzdiff/MATRIX.md`; outcome semantics in `server/authzdiff/OUTCOMES.md`.
- **Cross-layer authz differential harness.** `server/authzdiff` runs each operation on three layers: core called directly, the real REST router and the real gRPC server, each leg on its own fresh copy of a seeded SQLite template. Principals: fixed named ones (no role, viewer, project admin, global admin, actor 0, an expired grant, a suspended account, a restricted PAT) plus permission sets generated from each operation's own requirement (leave-one-out, single-permission, distractors), held directly, through a group, or by a machine. Oracle 1 asserts the layers agree; Oracle 2 compares each layer against a reference model over the role's actual permissions. Every flagged case is assigned to a known finding by an exact shape rule, or it is `unexplained`. `TestAuthzDiffSmoke` (default `go test`) and `FuzzAuthzDiff` fail on an unexplained case; the exhaustive sweep (`AUTHZDIFF_SWEEP=1`) fails on one under `AUTHZDIFF_STRICT=1`. Operation coverage is derived from `matrix.json` (`server/authzdiff/COVERAGE.md`, `COVERAGE-ALL.md`, freshness-checked).
- **Planted-defect self-test.** `TestPlantsAreDetected` applies four planted authorization defects with `go test -overlay` (a name-based role check in core, a removed gRPC machine-token guard, a removed REST router gate, a removed gRPC group guard) and fails if the harness stops reporting the planted operation as unexplained. It runs in the new `authzdiff-plants` CI job.

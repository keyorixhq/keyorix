### Testing
- **`scripts/airgap-e2e.sh` runs for any caller uid.** Every container is started as the caller (`--user "$(id -u):$(id -g)"`, plus `--userns=keep-id` under rootless podman), so the 0700 work dirs and 0600 env files it bind-mounts are readable; it used to work only as uid 1001 (#4700). A health-wait timeout now prints the container state and `logs --tail 100` instead of only "never became healthy". A fake-engine test (`scripts/e2e/lib/airgap-e2e_test.sh`, run by `go test ./scripts/e2e/lib/`) covers both; the real container run stays manual.
- **`make e2e-smoke-upgrade` upgrades from v0.96.3.** The default `KEYORIX_E2E_UPGRADE_FROM_TAG` moved from v0.95.1, a skipped-minor hop `docs/UPGRADING.md` §1a does not support, to the previous minor's last patch. The old binary's `admin init` gets `--dev` when its `--help` lists it (the harness drives plain HTTP and v0.96.x writes the TLS baseline otherwise), and the old config's `require_mfa: true` is opted out visibly so the old server's admin can create data (#4700).
- **The dynamic-secret journey opts in to the plaintext Postgres target it uses.** `TestJourney_DynamicSecretLifecycle` (nightly `e2e-journeys-containers`) registered a Postgres target with `sslmode=disable`, which the server has refused since the dynamic-secret transport policy (`admin_dsn option "sslmode=disable" is not allowed for postgres backends`); the journey's server config now sets `dynamic_secrets.insecure_allow_plaintext_dynamic_secret_transport: true` for its throwaway no-TLS container (#4699).

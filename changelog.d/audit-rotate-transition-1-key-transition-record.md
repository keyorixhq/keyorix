### Security
- **`encryption rotate-kek` and `migrate-provider` now carry the audit verification state over to the new key.** Before any key file is written, the command verifies the audit chain under the current key. It then records a key transition signed by the old checkpoint key and, over that, by the new one. Once the new key files commit, the command finishes the transition: the verification state, the audit high-water mark and the retention anchor are re-signed under the new key, a `system.audit_key_transition` event is appended, and a fresh checkpoint is written. If the command is interrupted, the server finishes the transition at its next start. After an honest key change, `keyorix audit verify` and offline `verify-audit` with the new checkpoint key read `VALID`. This supersedes the `other key epoch` behaviour change listed for #3621, and it fixes installs with a retention purge reading `BROKEN` after a key change. A recorded break or discontinuity is carried over, never cleared. A missing, forged or wrong-epoch transition record reads `BROKEN` (`audit verification state discontinuity (key transition)`). New `verify-audit --previous-checkpoint-key-file` (repeatable) checks each transition's old-key signature. Rotate with the new binary only: a later key change by an older binary reads `BROKEN`.

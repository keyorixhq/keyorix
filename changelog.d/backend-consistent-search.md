### Fixed
- **Name and user search now ignore case the same way on SQLite and PostgreSQL.** Searching secrets by name on SQLite only matched upper and lower case for ASCII letters, so `äö` did not find `ÄÖ` (PostgreSQL did). The `username` and `email` filters of the user list were case-insensitive on SQLite but case-sensitive on PostgreSQL. All three are now case-insensitive for any script (search term and stored value both NFC-normalized, so a name stored in decomposed form is found too; per-character lower-casing; Greek final sigma treated as sigma) on both backends. PostgreSQL needs a UTF8 database encoding for these filters. No schema change; SQLite gets a small `keyorix_fold` SQL function registered on its connections. `%`, `_` and `\` in a search term are still matched literally.

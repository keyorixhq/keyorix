### Security
- **MFA functions now refuse inactive acting accounts.** `ActivateMFA`, `DisableMFA`, and `RegenerateMFARecoveryCodes` call `requireActorActive` before any password check or business logic, so a suspended or inactive account cannot activate, disable, or regenerate MFA credentials from the core layer. The refusal uses the generic "invalid code or password" message (same as a wrong credential) so account state is not leaked by the error text (anti-enumeration). Guarded by `TestSuspendedActorRefusedAtEntryPoints` and `TestMFAOpsRefusalTextMatchesWrongPassword`. This is defense in depth: the REST/gRPC transports already refuse a suspended account at authentication.

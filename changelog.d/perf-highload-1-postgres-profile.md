### Changed
- **The bundled PostgreSQL now runs the recommended profile by default.** The Helm chart's `postgresql.settings` and `docker-compose.yml`'s `postgres` service ship the "Production PostgreSQL profile" of `docs/PERFORMANCE.md` (`shared_buffers`, `effective_cache_size`, `wal_buffers`, `wal_compression=lz4`, `checkpoint_timeout`, `max_wal_size`), sized for the chart's 1Gi PostgreSQL memory limit; compose takes the two memory sizes from `KEYORIX_PG_SHARED_BUFFERS` / `KEYORIX_PG_EFFECTIVE_CACHE_SIZE`. Durability settings are untouched (the chart still refuses non-durable values). Helm merges the map with yours: set a key to `null` in a values file to drop it. A release upgraded with `--reuse-values` gets the profile too unless it set `postgresql.settings` itself (then its own map is kept as is). The docs now give the reason for each setting, and why `commit_delay` stays off.

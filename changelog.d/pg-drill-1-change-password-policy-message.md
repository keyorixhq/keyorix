### Fixed
- **`POST /auth/change-password` says which password rule the new password broke.** A new password that contained the username, or reused a recent password, was answered with "an internal error occurred; please try again or contact support" (HTTP 400) and the real reason only reached the server log, so a user logging in with a one-time password could not tell what to change. The policy message ("password must not contain your username, email, or display name") is now returned; other failures keep the generic text. Guarded by `TestChangePassword_PolicyRefusalNamesTheRule`.

### Security
- **The evidence-delivery webhook no longer logs or returns its configured endpoint URL (REDACT-URLS-1).** The endpoint can carry a token in the userinfo, path or query. The `insecure_skip_verify` startup warning, the endpoint-validation errors (invalid URL, plaintext `http://`, unsupported scheme, private target) and the delivery errors from a failed POST all printed it, the last two through the wrapped `*url.Error`. They now name the destination as scheme and host only and drop the `*url.Error` layer, keeping `errors.Is` on the underlying failure.
- **Configured endpoint URLs no longer reach logs and error text elsewhere (REDACT-URLS-1).** A new repo-wide guard (`internal/urlleakguard`) flags `log.*`, `fmt.Errorf`, `errors.New` and `slog` calls that format a value named like `Endpoint`, `URL` or `DSN`. Its hits are fixed: the RFC 3161 checkpoint-notary URL (startup log lines, validation errors and the delivery error, including the wrapped `*url.Error`), the evidence-webhook and notification-webhook "enabled" startup lines, the `keyorix-k8s-sync` startup lines, the SSO `redirect_url` validation error, and the redirect-refusal errors of the Kubernetes dynamic-secrets client, the k8s-sync fetcher, the MCP client and the notary, which quoted a server-controlled redirect target. They name the destination as scheme and host only.

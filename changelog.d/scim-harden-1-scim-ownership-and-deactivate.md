### Security
- **SCIM can no longer touch accounts that were only claimed through SSO (#3418).** A native account that signed in once through SSO (matched by verified email) used to count as SCIM-managed, so the SCIM bearer token could read, edit, deactivate, delete and add to groups that account, native administrators included. SCIM now acts only on accounts it created: an external id outside the `sso:` namespace. A SCIM create whose `externalId` starts with `sso:` is refused with 400. Accounts SCIM created keep being managed after their users sign in through SSO. A refused id still answers exactly like a missing one (404).
- **SCIM deactivation now revokes personal access tokens (#3419).** `PATCH`/`PUT` with `active=false` (how Okta and Entra disable a user) revokes every PAT of the user in the same transaction as the deactivation and evicts them from the auth cache, as SCIM `DELETE` already did. A later `active=true` no longer brings old tokens back. If the revoke fails, the whole deactivation is rolled back and the IdP gets an error to retry.

### Changed
- **Operator action for installs that use SSO just-in-time provisioning together with SCIM.** An account created by SSO JIT provisioning (external id `sso:<provider>:<subject>`) is no longer visible to or changeable by SCIM, even if the IdP's SCIM sync previously matched it by `userName`. The IdP will report "not found" for updates and a conflict (409) when it tries to create that user. Offboard such accounts with the admin API or console (suspend or delete), or delete the account and let SCIM provision it again.

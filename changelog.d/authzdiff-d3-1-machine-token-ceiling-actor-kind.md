### Security
- **Fixed: a machine identity holding `roles.assign` at a project could not mint a token for another machine identity in that project, even though both the HTTP and gRPC routes for that call already admitted it.** `IssueMachineToken`'s privilege-ceiling check was evaluating the authority of a hardcoded `(user, actor-id)` pair instead of the real calling principal, and a machine caller's user-id is always `0` — so the ceiling always evaluated "user 0, no roles" and refused every machine actor unconditionally, regardless of its real authority (authzdiff cross-layer differential harness waiver known-03). Also fixed: this same endpoint returned `500` instead of `403` for a legitimate privilege-ceiling refusal, since the error wasn't matched by `errors.Is` before the response's status-code switch.

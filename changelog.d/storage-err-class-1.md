### Fixed
- **A storage outage no longer reads as "not found" on revoke paths.** Revoking or suspending a machine identity, revoking a machine token, deleting an OIDC binding, transitioning a project membership, revoking or resending an invitation, resolving or withdrawing an access request, revoking a dynamic-secret lease, and attesting an access-review grant used to turn ANY storage read error into "... not found" (HTTP 404, gRPC NotFound), so during a database outage an operator concluded the principal was already gone while the revoke had never been applied. A read fault is now `core.ErrStorageReadUnavailable`: REST answers 503 with `Retry-After` and code `storage_unavailable`, gRPC `Unavailable` (reason `storage_unavailable`); bulk delete, bulk rename and attestation report a distinct "storage temporarily unavailable, please retry". A true not-found and a cross-project mismatch still give one identical "not found" answer. Guarded by `TestNoStorageReadErrorFoldedIntoNotFound` (report-only on its first day).

### Security
- **MFA functions now refuse inactive acting accounts with a generic error.** `ActivateMFA`, `DisableMFA`, and `RegenerateMFARecoveryCodes` call `requireActorActive` before any password check or business logic, and the refusal is re-wrapped as `mfaActiveGuardRefusal` so a suspended account receives the same "invalid code or password" message as a wrong credential (anti-enumeration). The error satisfies `errors.Is(err, ErrPermissionDenied)` for correct transport 403 mapping. Guarded by `TestSuspendedActorRefusedAtEntryPoints`, `TestCoreRefusesSuspendedActor`, and `TestMFAOpsRefusalTextMatchesWrongPassword`.

### Fixed
- **Authzdiff oracle no longer misclassifies HTTP 400 as `Other`.** REST HTTP 400 responses are now mapped to the new `PreconditionFailed` outcome instead of `Other`. The reference model returns `PreconditionFailed` when a principal passes all RBAC checks but lacks the required MFA state (mfa\_activate/mfa\_disable/mfa\_recovery-codes.regenerate). This closed waiver `known-12` (tracking issue #4525) and eliminates the unexplained mapping gap for MFA ops without required MFA state.
- **`mfa.enroll` (`BeginMFAEnrollment`) is now a full differential op.** The authzdiff test fixture wires an enabled `authEncryptor` so `BeginMFAEnrollment` can succeed; the reference model's `noMFARequired` predicate catches the `pkMFAUser` (mfa\_enabled=true) case as `PreconditionFailed`; zero unexplained cases in `TestV5ext6bStrictSweep`.

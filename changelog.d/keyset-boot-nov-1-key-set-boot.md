### Security
- **Two servers on one config can no longer both hold "the" DEK lock (#4249).** A relative `storage.encryption.dek_path` put `dek.lock` in each process's working directory, so a server started from another directory took another lock, did not exclude the first, and served the same database. Relative key paths are now defined against the config file's directory (like `storage.database.path`), and the server and `admin encryption` commands refuse to start from any other directory, naming the key and the fix (use absolute paths, or start from the config's directory). The configured values are not rewritten, so backup archives are unaffected. Upgrade note: `docs/upgrading.d/relative-key-paths-config-directory.md`.

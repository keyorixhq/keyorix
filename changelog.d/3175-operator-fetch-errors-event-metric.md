### Changed
- **The Kubernetes operator and the k8s sync agent now report "Keyorix could not answer" instead of a bare `SyncError` / `failed`.** When Keyorix is unreachable, a request times out, or the server answers 5xx, the target Secret is still kept untouched and the sync is retried with backoff, as before. The operator now sets `Ready=False` reason `KeyorixUnreachable` (was `SyncError` for these cases), raises one Warning Event `KeyorixUnreachable` when the state is entered (not on every retry), counts each failed reconcile in `keyorix_operator_fetch_errors_total{reason="unreachable|timeout|server_error"}`, and raises a Normal Event `KeyorixRecovered` on the first successful read. Alerts that match `Ready` reason `SyncError` for an outage should also match `KeyorixUnreachable`. k8s-sync counts the target `failed` and `keyorix_unreachable` (`keyorix_k8s_sync_secrets_total{outcome="keyorix_unreachable"}`, `/status` `keyorix_unreachable`, `keyorix_unreachable=N` in the pass summary) and logs `KeyorixUnreachable (reason)`. Classification comes from the transport error and the status code only; a cancelled context and a plain 4xx stay unclassified. Other operator failures (missing token Secret, apply error) remain `SyncError`. Decision: Andrei, 2026-10-13 (review REVIEW-3175B point 1). The operator and k8s-sync docs tables are updated.

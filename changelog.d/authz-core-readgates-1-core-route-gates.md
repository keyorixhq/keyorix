### Security
- **Core enforces the route-gate permission of 22 mutating operations (#4161).** The core entry points behind secret auto-rotate, rotate, rollback, copy, move, tags and description, share revoke, environment clone and copy-secrets, role update, delete and permission add, user create (with or without project assignments), user role set, group restore, role assignment and member add, project restore, global invitation and bulk access-request approval now check the permission their REST route group and gRPC method already required (`roles.read`, `users.read`, the per-secret `secrets.write`, `secrets.write` on a copy target, `roles.assign`, ...), for the human or machine actor on the request, and refuse with `ErrPermissionDenied` (REST 403, gRPC PermissionDenied). Ownership of a secret alone no longer satisfies the per-secret `secrets.write` gate in core on these operations, as it never did at the transports. Defence in depth: every REST and gRPC route already refused these callers, so no client sees a change. Guarded by `TestCoreEnforcesRouteGate` (server/authzdiff); authzdiff waiver known-04 removed.

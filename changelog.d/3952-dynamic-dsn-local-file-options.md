### Security
- **A project admin can no longer make the server read or send its own files or ambient credentials through a dynamic-secret `admin_dsn`.** Only the host of an `admin_dsn` was checked. A MySQL DSN with `allowAllFiles=true` let a rogue MySQL server (on any public address) answer the first statement with a `LOCAL INFILE` request, and the driver sent back any file the server could read (config, key material). MongoDB `tls*File` / `ssl*File` and PostgreSQL `sslrootcert`, `sslcert`, `sslkey`, `passfile`, `servicefile` and `service` made the driver read paths on the server's disk (an existence and parse oracle; the errors were already masked). A MongoDB DSN with `authMechanism=MONGODB-OIDC` (also `MONGODB-AWS`, `GSSAPI`) made the driver present the server's own credentials to the target host: the pod service-account token (or the file named by `AZURE_FEDERATED_TOKEN_FILE` / `AWS_WEB_IDENTITY_TOKEN_FILE`), the Azure/GCP metadata-endpoint tokens, or the AWS environment credentials. These options and mechanisms are now refused when the config is created and again on every connection, so configs stored earlier are covered too; the API names only the refused option. Guarded by `TestMySQLEngineNeverSendsLocalFilesToTheServer` and `TestLocalFileOptionsCoverTheDrivers`.

### Added
- **Operator and k8s-sync: suspended and expired source secrets are reported, never deleted.** A referenced Keyorix secret that is expired is retained in the cluster; one that is suspended is retained by default, or its managed keys are emptied with the new `KeyorixSecret` field `spec.onSuspend: Retain|Clear` (k8s-sync: `on_suspend: retain|clear`, Helm `onSuspend`). The Secret object is never deleted and a Secret the operator does not own is never touched; resuming restores the data on the next reconcile. Each state raises a `SourceSecretHealthy=False` condition (operator), a Warning Event `SourceSecretSuspended` / `SourceSecretExpired` (operator; a log line in k8s-sync) and a metric (`keyorix_operator_source_secrets{state}`; `keyorix_k8s_sync_secrets_total{outcome="source_suspended|source_expired|source_expiring"}`), cleared on recovery. Warnings also fire 30, 7 and 1 days ahead of an expiry. Fetch failures (server unreachable, timeouts, 5xx) still never modify the target Secret. The CRD change is additive and the default keeps the previous behaviour (the target Secret is left as is).

### Fixed
- **`GET /api/v1/secrets/{id}/certificate` maps secret-state refusals like the value routes.** A suspended secret was 400 and an expired one 500; both are now 409 `SecretSuspended` / `SecretExpired`, and a read outside the access schedule is 403 `SecretAccessOutsideSchedule`, with the same fixed messages. The caller is authorized before the state is revealed, as on the value routes.

### Testing
- **No-leak coverage past the route gate.** New handler-level tests call each value-disclosing handler (by id, by ref, certificate, render) as a caller that passes the route gate but fails the per-secret permission check, against suspended, expired and out-of-schedule secrets, and assert it sees exactly what it saw before the state applied (for render, also exactly what a missing secret answers). A reorder of the state guard ahead of the permission check inside core is now caught.

### Added
- **`scripts/release/verify-release.sh TAG`: customer-side release verification.** Checks the GitHub Release (32 assets, `checksums.txt` vs every file, cosign/certificate/signature of `checksums.txt`, CycloneDX SBOMs, SLSA provenance of the 14 binaries), the release and docker-publish workflow runs including the Trivy gate steps, the 6 images (tags, platforms, BuildKit SBOM and provenance, cosign signature, GitHub attestation) and the 3 Helm charts (version, appVersion, signature). Read access only; exits 1 on any failure and 2 when checks could not run. Image and chart signatures need cosign >= 3 (they are OCI referrers; with an older cosign those nine checks are SKIPped with a precondition message, never FAILed), a GitHub API rate limit is a SKIP, not a FAIL, and the BuildKit SBOM layer is matched on its real predicate type `https://spdx.dev/Document`. `--self-test` runs it against fixtures with no network, including a real v0.96.3 BuildKit attestation manifest. Guide: `docs/operator/verifying-releases.md` (includes the air-gapped/mirror variant).

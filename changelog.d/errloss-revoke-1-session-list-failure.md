### Security
- **A failed session listing no longer silently skips auth-cache eviction on revocation.** Password change, MFA/WebAuthn enrolment, setup-token consume, suspend, deactivate, delete, SCIM deprovision and the admin session purge listed the user's session-token hashes with the error discarded, so a read failure evicted nothing and logged nothing while the code promised "immediately". The listing is now retried once; if it still fails the revocation still succeeds, a `SECURITY:` line is logged, an `auth.session_revocation_failed` audit event is written, and every auth-cache entry of the user is evicted (new `middleware.InvalidateUserTokenCache`). Guarded by `TestSessionListFailure_*` (internal/core) and `TestInvalidateUserTokenCache_*` (server/middleware).

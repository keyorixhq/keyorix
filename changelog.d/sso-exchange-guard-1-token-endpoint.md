### Security
- **The SSO code exchange no longer uses an unguarded HTTP client (#4738).** The OIDC authorization-code exchange ran on `http.DefaultClient`, so a compromised identity provider could aim it, through its discovery document's `token_endpoint` or a redirect, at an internal or cloud-metadata address, with the client secret and the code. The exchange now runs on the discovery client (link-local dial guard, redirects only to the same host and port and never from https to http), and discovery refuses a `token_endpoint` that is not on the issuer's host unless that host is listed in the new `sso.providers[].token_endpoint_hosts`. A provider whose token endpoint is on another domain (for example Amazon Cognito) is skipped at start-up until its host is listed: see `docs/upgrading.d/sso-token-endpoint-host-check.md`.

### Changed
- **Boot failures exit 78 or 75 instead of 1, and the shipped systemd unit stops restarting on 78.** A start that only an operator can fix (refused config, missing or unusable key material, missing or wrong master passphrase, database login refused) exits 78; a dependency that may come back (cloud KMS or remote database unreachable, or a KMS answering 5xx or throttling) exits 75; everything else stays 1. One plain hint line is printed last on stderr. `deploy/edge/keyorix-server.service` gets `RestartPreventExitStatus=78` and `RestartSec=30` (was 5: one delay for every restart, crashes included). `deploy/edge/edge_exit_codes_test.go` fails if the unit and `server/boot_exit.go` disagree; `docs/edge-deployment.md` §7a and an upgrade note say what happens on each class. Not run: a real systemd, a container start (pending e2e VM).

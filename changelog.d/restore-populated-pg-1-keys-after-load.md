### Fixed
- **`admin restore --overwrite-existing` onto a populated PostgreSQL database replaced the key files, then failed.** The archive's key files were installed before the row load, and the load then failed on the first primary key the target already held, leaving the old database next to the new keys (the old keys only survived as `*.pre-restore-<timestamp>`). A PostgreSQL target that holds Keyorix rows is now refused before anything is extracted, migrated or installed, even with `--overwrite-existing` (that flag still moves key files aside and still accepts the empty schema an interrupted restore leaves). Key files are now installed only after the load transaction has committed, so any earlier failure leaves them untouched, and a SQLite database moved aside by `--overwrite-existing` is put back. Guarded by `TestAdminRestore_Postgres_OverwriteExisting_*` and `TestAdminRestore_SQLite_OverwriteExisting_LoadFailure_RestoresOldDatabase`; invariant `INV-ADMIN-restore-keys-after-load`.

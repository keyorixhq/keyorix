### Fixed
- **More storage read faults no longer read as "not found", "denied" or "invalid".** A read fault now answers 503 + `Retry-After` (code `storage_unavailable`) over REST and `Unavailable` over gRPC, while a true not-found keeps its 404 / `NotFound`. Fixed: a secret access request whose secret cannot be read (`RequestSecretAccess`); gRPC `UpdateSecret`/`DeleteSecret` when the permission lookup is down and every gRPC scoped-target fetch (secret, dynamic-secret config) for a caller who holds the permission globally (closes the two gRPC rows of #3873); template rendering of a referenced secret; the handler pre-checks of project access requests, secret sharing, share listing, leaving a share, and migrating a user to a machine identity; and `core.GetSecret` itself, which no longer reports a read fault as "secret not found". A caller without global standing keeps the uniform denial for an unreadable target, so a fault adds no existence signal. Bulk delete's `failed[].error` was already a fixed message: unchanged.

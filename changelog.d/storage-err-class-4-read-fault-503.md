### Fixed
- **More storage read faults no longer read as "not found", "denied" or "invalid".** A read fault now answers 503 + `Retry-After` (code `storage_unavailable`) over REST and `Unavailable` over gRPC, while a true not-found keeps its 404 / `NotFound`. Fixed: the by-reference value read (`GET /secrets/value?ref=`) when `core.ResolveSecretRef` cannot read the secret; creating and reading secret access requests; gRPC `UpdateSecret`/`DeleteSecret` when the permission lookup is down and every gRPC scoped-target fetch (secret, dynamic-secret config) for a caller who holds the permission globally (closes the two gRPC rows of #3873); `POST /secrets/{id}/copy` source read (was 500); template rendering of a referenced secret; and the handler pre-checks of folder creation (parent read), project access requests, secret sharing, share listing, leaving a share, and migrating a user to a machine identity. A caller without global standing keeps the uniform denial for an unreadable target, so a fault adds no existence signal. Bulk delete's `failed[].error` was already a fixed message: unchanged.

### Fixed
- **`keyorix system init` with no `--admin-email` now works.** The default was `admin@localhost`, which the server's email rule refuses, so a bare `system init` always failed. The default is now the placeholder `admin@keyorix.local` (it has no mailbox: pass your own address to receive password-reset mail), and `--help` says so.
- **`POST /system/init` answers rejected admin details 400, not 403.** A malformed email or username from a caller who holds the bootstrap token now returns 400 with the typed code `ValidationError` and `details.field` naming the input. A wrong or missing bootstrap token, and a server with no token configured, are still 403, and the token is still checked before the details, so the answer tells a caller without the token nothing about validation. `keyorix system init` prints the validation text with the flag to fix (`--admin-email`, `--admin-username`) instead of the "ask a project admin / request access" hint; it recognises the same refusal from a server that still answers it 403.
- **`keyorix audit verify` on a sealed chain says SEALED, with the seal text.** It used to print `FAILED (first broken id 0): ` with an empty reason. Text output is now `Audit chain: SEALED` with a `seal:` line (seal number, time, operator) from the server's `state_reason`; `--json` keeps `status: "sealed"` and fills `reason` with the same text. The exit status stays 1, like BROKEN and NOT PROVEN: in this CLI 4 means "permission denied", so it is not aligned with `verify-audit`'s 4 for SEALED (documented in the audit-chain-break runbook, section 7).
- **`keyorix break-glass activate` and `list` say when an activation went through the degraded (owed-audit) path.** `activate` prints one `DEGRADED:` line after the first line (the audit log was refusing writes, the audit rows are owed, the grant expires sooner, review is mandatory). `list` adds an `AUDIT` column with `DEGRADED` (or `DEGRADED, settled` once the owed rows are written) and a one-line legend, only when some activation is degraded; a list without one is unchanged. The server already reported `degraded` and `audit_settled_at`; nothing on the wire changed.

- **INV-AUTHZDIFF-v5ext3-bulk-secret-gates** The authorization gate of `bulk.delete`, `bulk.rename`, `bulk.suspend`, and `resume.all` is bound into the differential and checked against the independent reference model. `bulk.delete`: secrets.delete@project router gate; core enforces the same permission via the per-item RBAC fallback in CheckSecretPermission; additionally, BulkDeleteSecrets calls GetSecretWithPermissionCheck before the delete step — this requires secrets.read (or ownership/ACL-read), which is NOT captured by the router model. Machine actors: BulkDeleteSecrets treats actorID=0 as the CLI caller, skipping permission checks → item IS deleted; core leg returns errNotAuthzLayer. `bulk.rename`, `bulk.suspend`, `resume.all`: secrets.write@project router gate; same per-item RBAC fallback shape. Machine actors: BulkRenameSecrets, SuspendProjectSecretsWithOptions, and ResumeProjectSecrets return an error immediately for actorID=0 → HTTP 400/500; machine actors return errNotAuthzLayer for all three ops. `resume.all` requires a pre-suspended fixture secret (perProject.suspendedSecretID, s-resume-fixture, suspended via SuspendSecret in the V5EXT3 seed) so the admin positive control gets n≥1 from ResumeProjectSecrets. Differential plant limitation: router gate removal for all four ops cannot be detected via differential plants — the per-item RBAC fallback (#r124) mirrors the router gate check for every user-actor principal; removing the router gate changes the HTTP status code (403→200+empty-result) but not the harness outcome classification. Guard: TestV5ext3StrictSweep (strict sweep over curated variations for all 4 ops; zero uncalibrated, zero unexplained) and TestBulkSecretRouterGatesPresent (structural check that the four router gate anchor strings exist exactly once in server/http/router.go; RED when any gate registration is absent or misnamed). What these guards do NOT verify: per-item ownership grants, bulk.rotate (deferred to V5EXT4), SCIM, MFA step-up (deferred to V5EXT4).

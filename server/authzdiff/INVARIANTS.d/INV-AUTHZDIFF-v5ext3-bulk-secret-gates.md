- **INV-AUTHZDIFF-v5ext3-bulk-secret-gates** The authorization gate of `bulk.delete`, `bulk.rename`, `bulk.suspend`, and `resume.all` is bound into the differential and checked against the independent reference model. `bulk.delete`: secrets.delete@project router gate; core enforces the same permission via the per-item RBAC fallback in CheckSecretPermission; additionally, BulkDeleteSecrets calls GetSecretWithPermissionCheck before the delete step, which requires secrets.read (or ownership/ACL-read) for a user actor; the model encodes that as `requirement.userPerms` (#4515, formerly waiver known-11). Machine actors: BulkDeleteSecrets treats actorID=0 as the CLI caller, skipping permission checks → item IS deleted; core leg returns errNotAuthzLayer. `bulk.rename`, `bulk.suspend`, `resume.all`: secrets.write@project router gate; same per-item RBAC fallback shape. `bulk.suspend` additionally decides the route gate in core: SuspendProjectSecretsWithOptions refuses an actor without secrets.write@project (ErrPermissionDenied, before any secret is read) even when a per-secret ACL write or share would pass the per-item re-check (#4161 row 25, formerly waiver known-04; TestSuspendProjectSecrets_ProjectGate). Since #4657 `resume.all`, `bulk.rename` and `secret.extend.expiring` (bound in ops_phase5_test.go, swept here because it shares the route gate) decide it in core the same way (Test{ResumeProjectSecrets,BulkRenameSecrets,ExtendExpiringSecrets}_ProjectGate). The fixture exposes the shape for each: in A the viewer holds a per-secret ACL secrets.write on s3 (sent in every bulk.rename batch next to the main secret), on s-resume-fixture and on the phase-5 expiring secret, so a core that decided per secret only would allow the viewer where REST refuses (red on main before #4657: one `unexplained` case per op). Machine actors: BulkRenameSecrets, SuspendProjectSecretsWithOptions, and ResumeProjectSecrets refuse actorID=0 with ErrPermissionDenied → HTTP 403 (#4514); the model marks them human-only (formerly waiver known-10); the core leg returns errNotAuthzLayer for machine actors on all three ops. `resume.all` requires a pre-suspended fixture secret (perProject.suspendedSecretID, s-resume-fixture, suspended via SuspendSecret in the V5EXT3 seed) so the admin positive control gets n≥1 from ResumeProjectSecrets. Differential plant limitation: router gate removal for all four ops cannot be detected via differential plants — the per-item RBAC fallback (#r124) mirrors the router gate check for every user-actor principal; removing the router gate changes the HTTP status code (403→200+empty-result) but not the harness outcome classification. Guard: TestV5ext3StrictSweep (strict sweep over curated variations for all 4 ops plus secret.extend.expiring, machine+holds included; zero uncalibrated, zero unexplained) and TestBulkSecretRouterGatesPresent (structural check that the four router gate anchor strings exist exactly once in server/http/router.go; RED when any gate registration is absent or misnamed). What these guards do NOT verify: per-item ownership grants, bulk.rotate (deferred to V5EXT4), SCIM, MFA step-up (deferred to V5EXT4).

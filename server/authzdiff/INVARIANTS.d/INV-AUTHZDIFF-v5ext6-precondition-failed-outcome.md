The reference model returns `PreconditionFailed` when a principal passes all RBAC and account-state checks but fails an MFA business-rule precondition (the `decide` function in `harness_test.go` strips `mfaRequired`/`pendingMFARequired` and re-evaluates — if the stripped model allows the principal, the denial is a precondition, not a permission gap). MFA ops for a principal without required MFA state now show `model=PreconditionFailed, rest=PreconditionFailed(400)` — no disagreement, no unexplained case. This closed waiver `known-12` (#4525). The `classify()` function adds new class labels for disagreements involving `PreconditionFailed` (e.g. `O2:allowed-but-model-precondition`, `mapping-gap:precondition-where-model-allows`). `restBadStatus` in `partition_test.go` is expanded to match `PreconditionFailed` + "Bad Request" (as well as `Other` + "Bad Request" or "Internal Server Error"), preserving `known-10`. Guard: `TestWaiverIDsMatchExplain` + `TestAuthzDiffWaiversNotExpired` + `TestV5ext5StrictSweep` (which now has zero unexplained cases for the three MFA ops with no required MFA state). What it does NOT verify: that a future HTTP 400 from an unrelated handler is not wrongly classified as `PreconditionFailed` — any new op returning 400 for a non-precondition reason must be tracked and waived.

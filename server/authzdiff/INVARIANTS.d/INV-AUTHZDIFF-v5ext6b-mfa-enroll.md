- **INV-AUTHZDIFF-v5ext6b-mfa-enroll** `mfa.enroll` (POST `/api/v1/auth/mfa/enroll`, `BeginMFAEnrollment`) is bound in the cross-layer authorization differential (Stage 5, V5EXT6B). It has no RBAC gate; `core_refusal="none"` (coreEnforced=false) and `coreGateExcluded=true` because `BeginMFAEnrollment` enforces only two business rules — an at-rest auth encryptor must be enabled, and `user.MFAEnabled` must be false — not an RBAC permission. The op is modelled `noMFARequired + accountState`: only `pkMFAUser` (mfa_enabled=true) is refused `ErrMFAAlreadyEnabled` → HTTP 400 (a client-safe message), which maps to `PreconditionFailed` (the model strips `noMFARequired` for an accountState op and finds the caller otherwise Allowed); every other authenticated principal without MFA is Allowed (a pending enrolment does NOT disqualify, so `pkMFAEnrollee` is Allowed too); a restricted PAT is Denied (`POST /auth/mfa/enroll` is in core's restricted-PAT write-refusal table, `patRefusesUngatedWrite`); a suspended actor is Denied. To make `BeginMFAEnrollment` reach a 2xx at all the harness wires a shared at-rest auth encryptor (`fixtures.enc`, an `encryption.Service` whose DEK is held in memory): `newCore(ls, fx.enc)` on every leg so each core decrypts the template's MFA secrets with the same key, and every seeded TOTP secret (pkMFAUser, pkMFAEnrollee, the two mfaReset TOTP admins) is written encrypted under `ports.MFASecretAAD`. The auth encryptor covers only MFA/auth secrets — secret VALUE storage stays in plaintext mode, so no other op's fixture changes. Guard: `TestV5ext6bStrictSweep` (11 cases, zero uncalibrated, zero unexplained) and `TestMFARouteGatesPresent` (the `BlockWhenImpersonating` anchor). Red proof (throwaway, never committed): deleting the `noMFARequired` check from `model.allowed` makes pkMFAUser pass the model while REST answers 400 → `O2:precondition-but-model-allowed` → `TestV5ext6bStrictSweep` fails; tree as committed → zero unexplained. What it does NOT verify: cryptographic validity of the returned `otpauth_uri` (only non-empty is checked) or that the secret validates against a TOTP code; enrolment idempotency (upsert of the pending secret); the `BlockWhenImpersonating` runtime refusal (structural anchor only).

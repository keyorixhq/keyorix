- **INV-ADMIN-backup-restore-roundtrip-preserves-logical-state** For any state S reachable
  by a sequence of ordinary core operations on an encrypted store, `admin restore` of
  `admin backup`(S) into a fresh data directory, opened through the real startup path,
  yields a store logically equal to S, and repeating the cycle changes nothing. "Logically
  equal" = every GORM table's rows (compared by parsed timestamp instant, so a cross-backend
  timezone re-encoding is not a difference), every wrapped key file (the restore checks each
  against the manifest's recorded SHA-256), and the audit hash-chain (the restore's own
  automatic verify-audit must report VALID). Three values are EXCLUDED, each a derived,
  non-application-owned quantity that legitimately does not survive a logical restore:
  `system_metadata.schema_epoch`/`schema_min_compatible_epoch` (regenerated by the TARGET
  binary's own migration — ADR-097/101; row count still matches); the trigger-maintained,
  `gorm:"<-:false"` `cache_epoch` on `secret_nodes`/`secret_versions` (a process-local
  read-path cache-generation stamp GORM never writes, so the loader's INSERT cannot carry a
  non-zero value — a restored server is a fresh process with an empty cache, so only
  within-process consistency matters; report finding BK-1); and the `admin.restore_completed`
  self-audit event the restore appends to the restored chain (the task's own exclusion list
  names "the restore audit event"). A backup or restore that REFUSES must do so with an
  explicit error and never silently corrupt; a restore that SUCCEEDS must satisfy the above.
  Every secret version must additionally still decrypt to its exact original plaintext under
  the RESTORED key files (an independent check that the wrapped DEK and ciphertext round-trip
  together, which byte-equality of ciphertext alone would not prove). Why: the sibling
  property test (`backup_restore_property_test.go`) seeds exactly one deterministic row per
  model and so never exercised arbitrary states, non-zero `cache_epoch`, or multi-version
  secrets — this metamorphic fuzzer does. Guard:
  `server/admin/backup_roundtrip_metamorphic_fuzz_test.go`
  (`FuzzBackupRestoreRoundTrip`; SQLite always, Postgres pg-gated on `KEYORIX_TEST_PG_DSN`).
  Not guarded here: completed DEK/KEK rotation and passphrase change as mid-sequence ops
  (the in-process harness retains the key-directory flock that the standalone CLI releases
  between processes — see the fuzzer's op-9 comment and the report's limitations); backup
  taken while a rotation is PENDING (covered by `backup_pending_rotation_test.go`, #4058/#4104)
  and stale `kek.salt.pending` (#4105).

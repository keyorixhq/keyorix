- **INV-SIEM-event-single-record** An outbound audit event (the spool JSONL record `json.Marshal(event)+'\n'`, the forwarder webhook payload, and the Datadog envelope) is always exactly ONE JSON line / object, and each field decodes to its stdlib-`encoding/json` reference round-trip — so a newline or delimiter embedded in `Description` (or any string field) can never forge a second record or inject a field (log-forging). Why: audit descriptions embed actor/project/secret names chosen by any authenticated user; a line-oriented SIEM must not ingest an attacker-authored second event (ML1 campaign, piece 4). Guard: `FuzzSIEMEventJSONForging` (`internal/audit/siem/siem_forging_fuzz_test.go`) — single-line / single-object / reference-round-trip oracle.

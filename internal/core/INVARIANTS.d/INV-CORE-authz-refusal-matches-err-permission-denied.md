- **INV-CORE-authz-refusal-matches-err-permission-denied** Every core refusal built from the i18n "ErrorPermissionDenied" text (via `permissionDeniedf` and the other typing helpers), and the specific sentinels `ErrSoDPermissionDenied`, `ErrRiskExceptionPermissionDenied`, `ErrMachinePrivilegeCeilingDenied`, the `ErrShare*` refusals and the restricted-classification gate refusals (classification_gate.go; not its "could not verify" storage-failure errors), match `core.ErrPermissionDenied` under `errors.Is`, with the text unchanged. The gate refusals also match their own `ErrClassificationGateDenied`, so a caller that folds `ErrPermissionDenied` into not-found to hide a secret's existence (`CopySecret`) returns a gate refusal, which comes only after the read permission was granted, as itself (403 with its reason, #3804). Not covered yet: `ErrBreakGlassListForbidden`, `ErrAccessOutsideSchedule`, `ErrConnectRefNotPermitted`, the SCIM i18n "ErrorNotAuthorized" refusals (scim_groups.go), and the text classifier in secret_read_denial.go. The guard checks only literal `i18n.T("ErrorPermissionDenied")` calls under the `i18n` import name, not aliased imports or other refusal texts. Callers classify with `errors.Is` on a sentinel, never by message text: the text is translated, and an unrelated error that says "permission denied" (an OS error) is not a refusal. Guard: `TestEveryErrorPermissionDeniedRefusalIsTyped`; `TestErrPermissionDenied_SpecificSentinelsMatchIt`; `TestRestrictedGateRefusal_Is403InEveryLocale` (server/http/handlers); `TestCopySecret_ClassificationGateRefusal_Is403WithReason` (server/http).

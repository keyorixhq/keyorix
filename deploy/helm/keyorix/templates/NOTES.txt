Keyorix has been deployed as release "{{ .Release.Name }}".

1. Wait for the pods to be ready:

   kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }} -w

2. Reach the UI:
{{- if .Values.ingress.enabled }}

   http{{ if .Values.ingress.tls }}s{{ end }}://{{ .Values.ingress.host }}
{{- else if .Values.web.enabled }}

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "keyorix.web.fullname" . }} 8080:{{ .Values.web.service.port }}
   open http://localhost:8080
{{- else }}

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "keyorix.server.fullname" . }} 8080:{{ .Values.server.service.port }}
{{- end }}
{{- if and .Values.ingress.enabled (not .Values.ingress.tls) }}

⚠️  WARNING — ingress.tls is empty, so this Ingress serves plaintext HTTP only.
    Session cookies, PATs, and login passwords will cross the wire unencrypted
    unless TLS already terminates upstream (e.g. a cloud load balancer). Set
    ingress.tls to enable HTTPS at this ingress, or confirm upstream TLS
    termination is in place.
{{- end }}

{{- if include "keyorix.hasAdminPassword" . }}

3. Log in with the admin you configured (auth.adminUsername="{{ .Values.auth.adminUsername }}"{{ if .Values.auth.existingSecret }}; its password is the KEYORIX_ADMIN_PASSWORD key of the "{{ .Values.auth.existingSecret }}" Secret{{ end }}).
{{- else }}

3. This render could not see an admin password: auth.adminPassword is empty and
   neither auth.existingSecretKeys.adminPassword nor a KEYORIX_ADMIN_PASSWORD key in
   the existing Secret was visible (helm template, --dry-run and GitOps renderers
   cannot read a live Secret).

   If your Secret does carry KEYORIX_ADMIN_PASSWORD, the server created the first
   admin on its first start: log in as auth.adminUsername="{{ .Values.auth.adminUsername }}" with that password, and skip
   the rest of this step.

   Otherwise initialise the first admin manually, over the network, against the
   server itself (not the web UI), using the bootstrap token. In a second terminal:

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "keyorix.server.fullname" . }} 8080:{{ .Values.server.service.port }}
{{- if .Values.secureBaseline.enabled }}

   The server speaks TLS only (secureBaseline.enabled), so the CLI must use https
   and trust the server certificate (the CLI has no skip-verify flag):

   kubectl -n {{ .Release.Namespace }} get secret {{ include "keyorix.secureBaseline.secretName" . }} \
     -o jsonpath='{.data.server\.crt}' | base64 -d > keyorix-server.crt
   chmod 600 keyorix-server.crt
   keyorix config set ca_file "$PWD/keyorix-server.crt"
{{- end }}

   kubectl -n {{ .Release.Namespace }} get secret {{ include "keyorix.secretName" . }} \
     -o jsonpath='{.data.KEYORIX_BOOTSTRAP_TOKEN}' | base64 -d; echo

   read -r -s -p 'Bootstrap token: ' KEYORIX_BOOTSTRAP_TOKEN; echo
   export KEYORIX_BOOTSTRAP_TOKEN
   keyorix system init --server http{{ if .Values.secureBaseline.enabled }}s{{ end }}://localhost:8080 --admin-username {{ .Values.auth.adminUsername }} --admin-email admin@example.com

   (Use your own address for --admin-email: init is rejected without a valid one.
   The CLI reads the token from KEYORIX_BOOTSTRAP_TOKEN and prompts for
   the admin password; neither belongs on the command line.)
{{- end }}

{{- if .Values.secureBaseline.enabled }}

Secure baseline is on: the server speaks TLS only, with the certificate in the
"{{ include "keyorix.secureBaseline.secretName" . }}" Secret (the web pod verifies it). To talk to the
server directly with the CLI, trust that certificate:

   kubectl -n {{ .Release.Namespace }} get secret {{ include "keyorix.secureBaseline.secretName" . }} \
     -o jsonpath='{.data.server\.crt}' | base64 -d > keyorix-server.crt
   keyorix config set ca_file "$PWD/keyorix-server.crt"

GET /metrics needs the token in the same Secret (key metrics_token).
{{- end }}

{{- if not .Values.auth.existingSecret }}

⚠️  This release's passwords came from Helm values, so Helm keeps them in its
    release record (helm get values). Prefer creating the Secret yourself from
    owner-only (0600) files and setting auth.existingSecret (chart README,
    "Quick start"). Never pass a password with --set or --from-literal: a
    command line is readable by every local user while it runs (ps) and stays
    in shell history and CI logs.
{{- end }}

⚠️  CRITICAL — back up the encryption keys volume
    The PVC "{{ include "keyorix.server.fullname" . }}-keys" holds the wrapped DEK
    and KEK salt. It is annotated helm.sh/resource-policy: keep, but if you lose it
    OR change auth.masterPassword, every stored secret becomes undecryptable.

⚠️  NetworkPolicy egress is on and the database is external, but
    networkPolicy.egress.databaseTo is empty: the server pod is denied egress to

{{- end }}
